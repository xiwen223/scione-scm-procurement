# 跟单预警看板后端接口设计

> 文档状态：按当前代码实现整理  
> 实现入口：`../../src/main/java/com/scione/scm/bill/interfaces/DeliveryAlertController.java`  
> 基础路径：`/api/v1/delivery-alerts`  
> 更新时间：2026-09-04

## 1. 文档目的

本文档描述跟单预警看板当前已经实现的 HTTP 接口契约，包括请求参数、响应模型、查询口径、异常规则和已知限制。本文档以 `DeliveryAlertController`、应用层 DTO、仓储实现及 `DeliveryAlertMapper.xml` 为准，不描述尚未落地的规划能力。

该模块是只读查询模块，数据来自领星 ERP 同步至本地 MySQL 的采购单、采购明细、采购计划和业务日志表，不提供新增、修改或删除接口。

## 2. 接口总览

| # | 方法 | 路径 | 用途 |
|---|---|---|---|
| 1 | GET | `/api/v1/delivery-alerts` | 分页查询跟单预警主事项 |
| 2 | GET | `/api/v1/delivery-alerts/summary` | 查询主事项汇总统计 |
| 3 | GET | `/api/v1/delivery-alerts/filter-options` | 查询供应商、采购员、仓库筛选项 |
| 4 | GET | `/api/v1/delivery-alerts/components` | 查询套装事项的组件列表 |
| 5 | GET | `/api/v1/delivery-alerts/{groupKey}` | 查询主事项标题及采购事实时间线 |
| 6 | GET | `/api/v1/delivery-alerts/{groupKey}/components/{componentId}` | 查询套装组件标题及采购单时间线 |

所有接口均为 GET。Controller 中没有声明 `@PreAuthorize`、`@Secured` 等权限注解；是否由网关或部署环境统一鉴权不在本模块代码范围内。

## 3. 公共约定

### 3.1 统一响应结构

所有接口返回 `ApiResponse<T>`：

| 字段 | 类型 | 必有 | 说明 |
|---|---|---|---|
| `code` | integer | 是 | 业务码，成功为 `0` |
| `message` | string | 是 | 成功时为 `操作成功` |
| `data` | T/null | 是 | 业务数据；失败时为 `null` |
| `timestamp` | long | 是 | 服务端构造响应时的 Unix 毫秒时间戳 |

成功响应示例：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {},
  "timestamp": 1788485400000
}
```

失败响应示例：

```json
{
  "code": 1099002,
  "message": "请求参数错误",
  "data": null,
  "timestamp": 1788485400000
}
```

### 3.2 日期和时间格式

| 场景 | 格式 |
|---|---|
| Query 参数 `startDate` | `yyyy-MM-dd` |
| 列表字段 `createdTime` | `yyyy-MM-dd HH:mm:ss` |
| 时间线字段 `eventTime` | `yyyy-MM-dd HH:mm` |

`startDate` 未传时固定使用 `2026-08-01`。该参数用于筛选 `po.create_time >= startDate`，包含起始日边界。

### 3.3 空字符串处理

列表、统计接口中的字符串 Query 参数会先执行以下标准化：

- `null`、空字符串或纯空白字符串转换为 `null`，即不参与筛选；
- 非空字符串去除首尾空白后参与查询。

`groupKey` 路径参数和组件接口的 `groupKey` Query 参数不执行上述标准化，也没有非空白、长度或格式校验。

### 3.4 主事项分组键

`groupKey` 是看板主事项的业务聚合键：

| 事项类型 | `groupKey` 取值 |
|---|---|
| 单品，或未关联到有效套装计划 | 采购单号 `orderSn` |
| 套装 | 套装采购计划号 `planSn` |

客户端必须从列表响应的 `groupKey` 取值，不应自行拼装。

### 3.5 类型和风险枚举

**事项类型**

| 参数值/响应值 | 含义 |
|---|---|
| `单品` | 单品事项 |
| `套装` | 套装事项 |

列表接口的 `type` 参数直接使用中文值，不使用 `single`、`kit`。

**风险等级**

| `riskLevel` | 中文 | 风险天数规则 |
|---|---|---|
| `done` | 已完成 | `riskDays = -1`，或 DTO 转换时 `riskDays = null` |
| `normal` | 正常 | `0 <= riskDays <= 10` |
| `due-soon` | 即将超期 | `10 < riskDays <= 15` |
| `overdue` | 超期 | `riskDays > 15` |

风险天数由采购单创建时间计算：采购单状态文本精确等于 `已完成` 时为 `-1`，否则为 `TIMESTAMPDIFF(DAY, create_time, NOW())`。一个主事项关联多条记录时取最大风险天数。

**快捷视图**

| `view` | 含义 | 查询条件 |
|---|---|---|
| `all` 或不传 | 全部 | 不增加条件 |
| `dueSoon` | 即将超期 | `10 < riskDays <= 15` |
| `overdue` | 超期 | `riskDays > 15` |
| `manual` | 无采购计划 | 类型包含 `无采购计划` |
| `kit` | 套装 | 类型包含 `套装` |

注意：快捷视图使用 camelCase 的 `dueSoon`，风险筛选使用连字符形式的 `due-soon`。

## 4. 接口详细设计

### 4.1 分页查询跟单预警主事项

```http
GET /api/v1/delivery-alerts
```

#### 4.1.1 Query 参数

| 参数 | 类型 | 必填 | 默认值 | 约束与说明 |
|---|---|---|---|---|
| `startDate` | string(date) | 否 | `2026-08-01` | 采购单创建时间起点，格式 `yyyy-MM-dd` |
| `keyword` | string | 否 | - | 模糊匹配采购单号、明细计划号、关联计划号、供应商、采购员、仓库、SKU、商品名 |
| `type` | string | 否 | - | 精确使用聚合类型：`单品`、`套装` |
| `supplier` | string | 否 | - | 供应商精确匹配 |
| `buyer` | string | 否 | - | 采购员姓名精确匹配 |
| `warehouse` | string | 否 | - | 仓库名称精确匹配 |
| `riskLevel` | string | 否 | - | `done`、`normal`、`due-soon`、`overdue` |
| `view` | string | 否 | - | `all`、`dueSoon`、`overdue`、`manual`、`kit` |
| `pageNum` | integer | 否 | `1` | 最小值为 1 |
| `pageSize` | integer | 否 | `6` | 取值范围 1～100 |

`keyword` 当前不匹配采购单状态和跟单备注。

#### 4.1.2 响应

响应类型：`ApiResponse<PageResult<DeliveryAlertListItemDTO>>`

`PageResult` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|

| `records` | array | 当前页主事项列表 |

`DeliveryAlertListItemDTO` 字段：

| 字段 | 类型 | 说明 |

| `groupKey` | string | 主事项分组键 |

| `typeDesc` | string | `types` 使用 `/` 拼接后的展示文本 |
| `orderSns` | string[] | 去重后的采购单号列表 |
| `planSns` | string[] | 去重后的采购计划号列表 |
| `optNames` | string[] | 去重后的采购员姓名列表 |
| `suppliers` | string[] | 去重后的供应商列表 |
| `warehouses` | string[] | 去重后的仓库列表 |
| `statusTexts` | string[] | 去重后的领星采购单状态文本列表 |
| `qtyPlan` | integer/null | 计划数量，计算规则见 5.3 |
| `qtyReady` | integer/null | 已就绪数量，计算规则见 5.3 |
| `riskDays` | integer/null | 分组内最大风险天数；已完成为 `-1` |
| `riskLevel` | string | 风险等级编码 |
| `riskLevelDesc` | string | 风险等级中文描述 |
| `createdTime` | string/null | 分组内最早采购单创建时间，格式 `yyyy-MM-dd HH:mm:ss` |

## 5. 查询与聚合口径

### 5.1 基础数据范围

主列表和统计以采购单明细为起点：

- `lx_purchase_order_item poi`：采购单明细；
- `lx_purchase_order po`：采购单头；
- `lx_purchase_plan pp`：采购计划；
- `JSON_TABLE(poi.relation_purchase_plan, '$[*]')`：展开明细关联的采购计划号；
- `lx_business_log`：详情时间线。

基础条件：

```sql
poi.is_delete = 0
AND po.create_time >= :startDate
AND po.status NOT IN (-1, 124)
```

当前业务链路中没有定义状态码 `-1`、`124` 的中文名称，接口仅按数字状态码排除，不在本文档中推断其业务含义。

### 5.2 筛选层级

`keyword`、`supplier`、`buyer`、`warehouse` 在采购明细行聚合前生效；`type`、`riskLevel`、`view` 在按 `groupKey` 聚合后生效。

因此，套装中仅某个组件命中聚合前条件时，聚合结果只保留命中的明细行，并不会先命中再恢复整套组件上下文。此时订单列表、供应商列表、数量和风险值可能随筛选条件改变。

### 5.3 数量口径

| 类型 | `qtyPlan` | `qtyReady` |
|---|---|---|
| 单品 | 分组内 `SUM(quantity_real)` | 分组内 `SUM(quantity_entry)` |
| 套装 | `MAX(quantity_plan)` | 当组件 `SUM(quantity_real) = SUM(quantity_entry)` 时取 `MAX(quantity_plan)`，否则为 `0` |

套装 `qtyReady` 是“全部明细是否到齐”的二值化口径，不表示当前实际可齐套套数。

### 5.4 排序规则

主列表固定排序：

1. `riskDays DESC`：风险天数高的优先；
2. `createdTime ASC`：创建时间早的优先；
3. `groupKey ASC`：分组键升序。

客户端不能通过参数修改排序规则。

### 5.5 详情日志关联

业务日志通过以下规则关联采购单：

```text
lx_business_log.business_id = "1_" + orderSn
```

套装主事项详情合并分组下所有采购单日志；组件详情只查询该组件所属采购单的日志。

## 6. 错误处理

| 场景 | HTTP 状态 | 业务码 | message |
|---|---:|---:|---|
| 缺少必填参数、日期/数字转换失败、分页参数越界 | 400 | `1099002` | `请求参数错误` |
| 主事项不存在 | 404 | `1099005` | `资源不存在` |
| 组件不存在或不属于指定套装 | 404 | `1099005` | `资源不存在` |
| HTTP 方法不支持 | 405 | `1099003` | 由公共结果码定义 |
| 数据库访问异常 | 500 | `1099102` | 由公共结果码定义 |
| 未处理的系统异常 | 500 | `1099001` | 由公共结果码定义 |

参数校验失败由全局异常处理器转换为统一响应。当前响应通常只返回通用的 `请求参数错误`，不会将 `@Min`、`@Max` 的具体校验文案拼接到 `message`。

## 7. 边界行为与已知限制

1. `type` 非法值会正常执行但通常返回空结果；非法的 `riskLevel` 或 `view` 没有匹配 SQL 分支，会被静默忽略。
2. `manual` 统计和 `view=manual` 当前判断类型是否包含 `无采购计划`，但基础 SQL 将未关联有效计划的记录标记为 `单品`，不会生成 `无采购计划`。因此当前实现中 `manual` 通常恒为 `0`，`view=manual` 通常返回空列表。
3. 列表和统计受 `startDate` 限制，组件列表和两类详情不受 `startDate` 限制。旧事项可能不在默认列表中，但仍可通过 `groupKey` 直接查询详情。
4. `GET /components` 查询不到数据时返回 HTTP 200 和空数组；两类详情查询不到数据时返回 HTTP 404。
5. 采购单完成判定依赖状态文本精确等于 `已完成`。其他状态文本原样返回，不转换为内部枚举。
6. DTO 将 `riskDays < 0` 且不等于 `-1` 的极端数据映射为 `normal`，而统计 SQL 的正常区间从 `0` 开始；未来创建时间等异常数据可能造成列表风险描述与统计数量不一致。
7. 多值字段使用 MySQL `GROUP_CONCAT(DISTINCT ...)` 聚合，再由 Java 按英文逗号拆分。原始字段包含英文逗号或聚合结果超过 `group_concat_max_len` 时可能出现误拆或截断。
8. `PageResult.of(...)` 当前未设置 `first`。客户端不应依赖该字段判断首页，可使用 `pageNum == 1`。
9. 极大的 `pageNum` 可能使 Java `int` 类型的 `(pageNum - 1) * pageSize` 溢出；接口当前未设置页码上限。
10. 当前代码未发现跟单预警接口的自动化测试，接口变更需同时复核 Controller、DTO 和 Mapper XML。
