### 4.1 分页查询跟单预警主事项

```http
GET /api/v1/delivery-alerts
```

#### 4.1.1 Query 参数

| 参数 | 类型 | 必填 | 默认值 | 约束与说明 |
|---|---|---|---|---|
| `keyword` | string | 否 | - | 模糊匹配采购单号、明细计划号、关联计划号、供应商、采购员、仓库、SKU、商品名 |
| `type` | string | 否 | - | 精确使用最终聚合类型：`单品`、`套装`、`合并下单` |
| `supplier` | string | 否 | - | 供应商精确匹配 |
| `buyer` | string | 否 | - | 采购员姓名精确匹配 |
| `warehouse` | string | 否 | - | 仓库名称精确匹配 |
| `riskLevel` | string | 否 | - | `done`、`normal`、`due-soon`、`overdue` |
| `view` | string | 否 | - | `all`、`dueSoon`、`overdue`、`manual`、`kit` |
| `pageNum` | integer | 否 | `1` | 最小值为 1 |
| `pageSize` | integer | 否 | `6` | 取值范围 1～100 |

`keyword` 当前不匹配采购单状态和跟单备注。数据起始日期由服务端配置，接口不接受 `startDate`。

#### 4.1.2 响应

响应类型：`ApiResponse<PageResult<DeliveryAlertListItemDTO>>`

`PageResult` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `pageNum` | integer | 当前页码 |
| `pageSize` | integer | 每页记录数 |
| `total` | long | 符合条件的分组总数 |
| `pages` | integer | 总页数，向上取整 |
| `first` | boolean/null | 是否第一页；当前接口使用的工厂方法未赋值，通常为 `null` |
| `last` | boolean | `pageNum >= pages`；空结果第一页也为 `true` |
| `records` | array | 当前页主事项列表 |

`DeliveryAlertListItemDTO` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `groupKey` | string | 主事项分组键；仅套装单品采为采购计划号，其他事项为采购单号 |
| `types` | string[] | 去重后的最终类型列表，值可为 `单品`、`套装`、`合并下单` |
| `typeDesc` | string | `types` 使用 `/` 拼接后的展示文本 |
| `purchaseMode` | string/null | `组合采`、`单品采` 或 `null`；同组并存时优先 `组合采` |
| `productName` | string/null | 完整分组内去重商品名，排序后使用 `、` 拼接 |
| `sku` | string/null | 完整分组内去重 SKU，排序后使用 `、` 拼接 |
| `skuCount` | long | 完整分组内非空白 SKU 的去重数量 |
| `orderSns` | string[] | 去重后的采购单号列表 |
| `planSns` | string[] | 去重后的采购计划号列表 |
| `optNames` | string[] | 去重后的采购员姓名列表 |
| `suppliers` | string[] | 去重后的供应商列表 |
| `warehouses` | string[] | 去重后的仓库列表 |
| `statusTexts` | string[] | 去重后的领星采购单状态文本列表 |
| `qtyPlan` | integer/null | 计划数量，计算规则见 5.3 |
| `qtyReady` | integer/null | 已就绪数量，计算规则见 5.3 |
| `riskDays` | integer/null | 完整分组内明细风险的最大值；仅全部明细进度完成时为 `-1` |
| `riskLevel` | string | 风险等级编码 |
| `riskLevelDesc` | string | 风险等级中文描述 |
| `createdTime` | string/null | 分组内最早采购单创建时间，格式 `yyyy-MM-dd HH:mm:ss` |

组合计划行在主列表中使用计划父商品口径：SKU 投影为 `pp.sku`，商品名优先使用 `pp.product_name`；非组合计划行使用采购明细的 `poi.sku`、`poi.product_name`。因此套装主事项的 `skuCount` 是主列表展示 SKU 的去重数量，通常为父 SKU 数量，不是商品明细或组件数量。

下方响应示例中的 `PP202608010001` 是套装单品采事项，因此商品类型为 `套装`，`groupKey` 为采购计划号且 `purchaseMode` 为 `单品采`。套装组合采事项返回采购单号形式的 `groupKey`（例如 `PO...`），商品类型为 `单品`，同时保留 `purchaseMode = 组合采`；如果该采购单号分组的有效 SKU 数或计划数大于 1，最终类型会进一步变为 `合并下单`。

### 4.2 查询汇总统计

```http
GET /api/v1/delivery-alerts/summary
```

#### 4.2.1 Query 参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `keyword` | string | 否 | - | 匹配规则同列表接口 |
| `supplier` | string | 否 | - | 供应商精确匹配 |
| `buyer` | string | 否 | - | 采购员精确匹配 |
| `warehouse` | string | 否 | - | 仓库精确匹配 |

该接口不接受 `startDate`、`type`、`riskLevel`、`view` 和分页参数。服务端先用起始日期及上述行级筛选选中候选 `groupKey`，再按完整有效行重新聚合并计算汇总统计。

#### 4.2.2 响应字段

响应类型：`ApiResponse<DeliveryAlertSummaryDTO>`

| 字段 | 类型 | 说明 |
|---|---|---|
| `total` | long | 分组总数 |
| `done` | long | 已完成数量 |
| `normal` | long | 正常数量 |
| `dueSoon` | long | 即将超期数量 |
| `overdue` | long | 超期数量 |
| `manual` | long | 聚合后 `plans` 为空的分组数 |
| `kit` | long | 最终类型集合包含 `套装` 的分组数，即套装单品采分组数 |

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "total": 28,
    "done": 5,
    "normal": 12,
    "dueSoon": 4,
```

#### 4.3.1 Query 参数

#### 4.3.2 响应字段

响应类型：`ApiResponse<FilterOptionsDTO>`

| 字段 | 类型 | 说明 |
|---|---|---|
| `suppliers` | string[] | 非空供应商，去重后升序排列 |
| `buyers` | string[] | 非空采购员，去重后升序排列 |

### 4.4 查询主事项商品明细

```http
GET /api/v1/delivery-alerts/components?groupKey={groupKey}
```

#### 4.4.1 Query 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `groupKey` | string | 是 | 列表返回的主事项分组键；仅套装单品采为采购计划号，其他事项为采购单号 |


#### 4.4.2 响应字段

响应类型：`ApiResponse<List<DeliveryAlertComponentDTO>>`

| 字段 | 类型 | 说明 |
|---|---|---|
| `componentId` | long | 采购单明细表 ID |
| `sku` | string/null | 商品明细 SKU |
| `productName` | string/null | 商品明细名称 |
| `orderSn` | string | 商品明细所属采购单号 |
| `planSn` | string/null | 关联采购计划号 |
| `purchaseMode` | string/null | 明细级采购模式：`组合采`、`单品采` 或 `null`；多计划关系并存时优先 `组合采` |
| `supplier` | string/null | 供应商 |
| `warehouse` | string/null | 仓库 |
| `optName` | string/null | 采购员 |
| `status` | string/null | 采购单状态文本 |
| `expected` | integer/null | 应交数量，来源 `quantity_real` |
| `arrived` | integer/null | 到货/入库数量，来源 `quantity_entry` |
| `qualified` | integer/null | 质检合格数量，来源 `quantity_qc` |
| `returned` | integer/null | 退货数量，来源 `MAX(quantity_return)` |
| `riskDays` | integer/null | 商品明细风险天数 |
| `riskLevel` | string | 风险等级编码 |
| `riskLevelDesc` | string | 风险等级中文描述 |

```json
{
  "code": 0,
  "message": "操作成功",
  "data": [
    {
      "componentId": 10001,
      "sku": "COMPONENT-SKU-001",
      "productName": "示例组件",
      "orderSn": "PO202608010001",
      "planSn": "PP202608010001",
      "purchaseMode": "组合采",
      "supplier": "示例供应商A",
      "warehouse": "东莞仓",
      "optName": "张三",
      "status": "部分入库",
      "expected": 100,
      "arrived": 80,
      "qualified": 78,
      "returned": 2,
      "riskDays": 18,
      "riskLevel": "overdue",
      "riskLevelDesc": "超期"
    }
  ],
  "timestamp": 1788485400000
}
```

`purchaseMode` 按当前采购明细与其关联采购计划计算，不复用主事项的聚合采购模式：`pp.is_combo = 1 AND pp.sku = poi.sku` 为 `组合采`，SKU 不同为 `单品采`，其他为 `null`。同一明细存在多条计划关系时，聚合结果优先 `组合采`。前端仅在明细值为 `组合采` 且存在 `planSn` 时，在采购计划号后显示组合采标签。

商品明细在 `quantity_real` 与 `quantity_entry` 均非空且 `quantity_entry >= quantity_real`，或所属采购单状态文本为 `已完成` 时视为已完成，返回 `riskDays = -1`、`riskLevel = done`；`0/0` 和超额入库视为完成，数量为空不视为完成。

`qualified` 和 `returned` 仅用于展示，不参与完成或风险判定，也不会从 `expected` 或 `arrived` 中扣减。商品明细固定按风险天数降序、采购单创建时间升序、SKU 升序排列。

### 4.5 查询主事项详情/时间线

```http
GET /api/v1/delivery-alerts/{groupKey}
```

#### 4.5.1 Path 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `groupKey` | string | 是 | 套装单品采分组使用采购计划号；单品、套装组合采和合并下单分组使用采购单号 |

#### 4.5.2 响应字段

响应类型：`ApiResponse<DeliveryAlertDetailDTO>`

| 字段 | 类型 | 说明 |
|---|---|---|
| `groupKey` | string | 主事项分组键 |
| `componentId` | long/null | 主事项详情固定为 `null` |
| `title` | string | 按分组内列表商品投影去重拼接：组合计划行使用 `COALESCE(pp.product_name, poi.product_name)`，其他行使用 `poi.product_name`；无名称时回退 `groupKey` |
| `component` | boolean | 主事项详情固定为 `false` |
| `events` | array | 严格归属于该 `groupKey` 的采购明细所涉及采购单的业务日志，按时间和日志 ID 升序 |

事件 `DeliveryAlertEventDTO`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | long | 业务日志 ID |
| `orderSn` | string | 日志所属采购单号 |
| `eventTime` | string/null | 事件时间，格式 `yyyy-MM-dd HH:mm` |
| `title` | string | 业务日志类型；空值回退为 `操作记录` |
| `description` | string | 日志详情；数据库 `null` 转为空字符串 |
| `operator` | string/null | 操作人姓名 |

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "groupKey": "PP202608010001",
    "componentId": null,
    "title": "示例套装商品",
    "component": false,
    "events": [
      {
        "id": 90001,
        "orderSn": "PO202608010001",
        "eventTime": "2026-08-01 09:30",
        "title": "创建采购单",
        "description": "采购单创建成功",
        "operator": "张三"
      }
    ]
  },
  "timestamp": 1788485400000
}
```

采购计划号分组只汇总套装单品采行涉及的采购单日志，可跨多个采购单；采购单号分组只有在该采购单存在未归入计划号分组的其他行时才查询该采购单日志。套装组合采按采购单号查询，详情标题按统一投影聚合，不会因关联组合计划而产生多个详情结果。日志本身仍是采购单粒度，同一采购单跨多个主事项时，其日志可能在这些事项中重复出现。

合法主事项没有业务日志时返回 `events: []`。主事项不存在时返回 404。

### 4.6 查询商品明细详情/时间线

```http
GET /api/v1/delivery-alerts/{groupKey}/components/{componentId}
```

#### 4.6.1 Path 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `groupKey` | string | 是 | 列表返回的分组键；仅套装单品采为采购计划号，其他事项为采购单号 |
| `componentId` | long | 是 | 采购单明细表 ID |

服务端同时校验商品明细 ID 和 `groupKey` 的归属关系。`componentId` 必须至少存在一条满足 4.4 商品明细范围的展开关系；不能使用与该明细没有关联关系的分组键读取。由于一个采购明细可以关联多个采购计划，同一 `componentId` 可能对多个 `groupKey` 均为合法。

#### 4.6.2 响应

响应类型仍为 `ApiResponse<DeliveryAlertDetailDTO>`，不是商品明细列表 DTO。

| 字段 | 商品明细详情取值 |
|---|---|
| `groupKey` | 请求中的主事项分组键 |
| `componentId` | 请求中的商品明细 ID |
| `title` | 优先取商品名，商品名为空时回退到 SKU |
| `component` | 仅当 `groupKey` 是套装单品采的采购计划号时为 `true`；套装组合采按采购单号分组时为 `false` |
| `events` | 商品明细所属采购单的全部业务日志 |

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "groupKey": "PP202608010001",
    "componentId": 10001,
    "title": "示例组件",
    "component": true,
    "events": [
      {
        "id": 90001,
        "orderSn": "PO202608010001",
        "eventTime": "2026-08-01 09:30",
        "title": "创建采购单",
        "description": "采购单创建成功",
        "operator": "张三"
      }
    ]
  },
  "timestamp": 1788485400000
}
```

商品明细时间线的数据粒度是采购单，不是单条采购明细。同一采购单下的多个商品明细会返回相同的采购单业务日志。商品明细不存在或不属于指定 `groupKey` 时返回 404。
